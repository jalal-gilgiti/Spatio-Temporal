# Learned Cardinality Estimation for Spatio-Temporal Queries in Moving-Object Databases: An Experimental Study

Code, data and results for the paper. Every number in the paper is a LaTeX macro in
`paper/numbers.tex`, and the figures are in `paper/figures/`. Both are generated from the
result files under `run/` by the scripts in this repository.

## What is included

| Dataset | Included | Not included |
|---|---|---|
| Porto (CC BY 4.0) | the 100,000-trip table used in the paper (`data/porto/`), all workloads with exact answers, all per-query predictions and results | the raw `train.csv` (download it from UCI) |
| Synthetic | generated by the code; the saved results (`run/revalidation/`) | — |
| T-Drive | query definitions without answers, SHA-256 hashes of the exact answers (`data/tdrive_answers.sha256`), aggregate results | trajectories, exact answers, per-query predictions, trained models, taxi lists |
| AIS | aggregate results only | points, trips, workloads and all per-query files |

T-Drive's licence forbids redistributing the data and derived files, and the AIS terms do
not permit redistribution. The scripts that rebuild every T-Drive and AIS table, workload
answer and result from the original downloads are included.

## Quick check (about 1 minute, no database)

```bash
uv sync                      # or: pip install numpy scipy pandas matplotlib scikit-learn psycopg[binary] torch pyarrow
uv run bash reproduce.sh     # or: PYTHON=python3 bash reproduce.sh
```

`reproduce.sh` works in a temporary copy and changes nothing in the repository. It

1. reruns the analysis on the released Porto per-query data: the accuracy and per-bucket
   tables (estimates clamped to [1, N] and unclamped), the decomposition of MobilityDB's
   error, the paired bootstrap tests and the plan-study metrics. It then checks that every
   rebuilt Porto row equals the released result tables;
2. evaluates every number of the paper and writes its status to
   `rebuilt/macro_status.csv`:
   - **rebuilt**: recomputed from released per-query data (Porto, synthetic) and equal to
     the paper;
   - **from released aggregates**: equal to the paper and computed from released aggregate
     results, for example the T-Drive and AIS rows of the accuracy tables;
   - **needs withheld data**: needs T-Drive or AIS per-query data (see below).

Two kinds of Porto values are computed jointly with T-Drive and AIS, so they match only
when all three datasets are present. These are the bootstrap intervals of the non-empty-query
table (one random stream across datasets) and the p-values of the paired tests (Holm
correction over all datasets). The point estimates in both match.

Tested with Python 3.11.15, numpy 2.4.6, scipy 1.17.1, pandas 3.0.5 and matplotlib 3.11.1.

## Database setup

Experiments need PostgreSQL 17.10, PostGIS 3.6.0, MobilityDB 1.3.0 (tag `v1.3.0`) and
pg_hint_plan (branch `PG17`). `scripts/setup_local_postgres.sh` builds them in user space
with conda and creates the database `mobilitydb` on port 5434. Workload timestamps have no
time zone and were run with the session time zone `Asia/Seoul`, which the setup script sets
on the database. All other server settings were defaults.

**Porto.** Load the table used in the paper and check all Porto answers against it:

```bash
python scripts/porto_table.py load          # creates porto_traj (bit-identical to the paper's table)
python scripts/rebuild_answers.py porto --prepare-join-table
```

**T-Drive.** Download the Microsoft Research T-Drive sample with
`scripts/download_real_datasets.sh`; `data/raw_downloads.sha256` lists the hashes of the
14 zip parts. Then:

```bash
python scripts/task7_dataset_validity.py --prepare-tdrive   # corrected 1M-trajectory pool, seed 70707
python scripts/task7b_headline.py                            # (re)creates tdrive_traj (first 100,000 trajectories), then runs the accuracy battery
python scripts/rebuild_answers.py tdrive --prepare-join-table --restore
```

`rebuild_answers.py tdrive` recomputes every T-Drive answer and checks each answer file
against `data/tdrive_answers.sha256`. With `--restore` it writes the answers back into the
workload files, so the experiment and analysis scripts can use them.

**AIS.** Danish Maritime Authority, daily files 2025-01-06 to 2025-02-19:

```bash
python scripts/vldbj_ais_prepare.py --start 2025-01-06 --days 45
python scripts/vldbj_ais_prepare.py --segment
python scripts/vldbj_ais_load.py
python scripts/vldbj_ais_battery.py     # workloads and the non-learned estimators
```

## Conventions

- Q-error is `max((t+1)/(e+1), (e+1)/(t+1))`, with the estimate `e` clamped to `[1, N]`
  (N = table rows), as a planner would clamp it. Unclamped values are in the
  `task1_*_table.csv` files without a `__planner` suffix.
- Learned-model results are the mean over seeds of the per-seed statistic (median, p95);
  the maximum is over all seeds and queries.
- Confidence intervals are paired query bootstraps (10,000 resamples).
- `docs/mobilitydb_root_cause.md` cites the MobilityDB 1.3.0 source lines behind the
  native estimate's undercount.
